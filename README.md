# UWGB_Alma_Letters
A repository to track customizations with Alma letters, which are written in XSL and enacted within the Alma environment with labels and XML.

Reflection:
As I began setting up this repository and considering how I would organize it, I exported the spreadsheet of all of the Alma letters, assuming I'd have to track which ones I'd worked on with something...like this spreadsheet.  And I dug through the original and modified versions of the letters that were somewhat haphazardly edited/tested/saved over the span of time.  We have been on Alma for 10 years now, and I definitely don't have all the iterations of the letters saved, and I have also always wanted to audit them for formatting, check for spelling errors, which can happen when the OOTB letters are written by developers in a foreign country.  But editing these letters can be scary and a project to audit them was completely overwhelming because there are so many letters and they are confusingly named, and you don't even know what triggers the letter to be sent half the time.  It's so easy to make a mistake in the coding and break the whole letter, especially when you want to do something complicated like write logic that makes a different message appear depending on what library is sending it.

But after playing with this project in GitHub just for a few hours, I'm CERTAIN that this is the tool I needed to make this project work.  My regret is I didn't know about it sooner... but I can also start using the project without taking the less complicated letters all the way back to their original form.  I can just start tracking them from where they are now, and use the project kanban board and the issues to keep track if the letters need any kind of modifications and what wording we might prefer.  Instead of tracking which letters I've started on in a spreadsheet and/or Microsoft Lists which crashes a lot, knowing which letters need what kind of attention, and saving the versions of the files individually by date/time stamps in yet another place, and fighting my annoyance to save every little bitty change... I can just keep track of ALL of those things in just ONE place, and saving even a little bitty change is just a commit button away.  I downloaded one of the GUI interfaces for this last project, and I'm so glad I did!  It is good that I fought through using the command line, but that level of user hostility would get in the way of my productivity for quite a long time since it feels like a foreign language.

I didn't set up the part of the project where there is an action, but I looked through the templates trying to find one that might apply.  I might consider doing something with the action that changes the label on an item based on pull requests, but I think that might still be more complicated than I'm ready for or need.
